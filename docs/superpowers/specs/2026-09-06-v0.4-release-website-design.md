# Fomo Live Feed v0.4.0 Release and Website Design

## Goal

Release the completed optional floating-window experience as Fomo Live Feed
v0.4.0, update the existing product website without redesigning it, and merge
the verified release work into `main`.

## Scope

### Extension release

- Change the product version from `0.3.0` to `0.4.0` everywhere it is declared
  or presented.
- Preserve the existing Side Panel as the default display mode.
- Present the completed floating-window mode as the primary v0.4.0 feature.
- Keep one shared feed state across Side Panel and floating-window surfaces,
  including local history, filters, trader annotations, and unread state.
- Build the Chrome Manifest V3 extension and produce a versioned ZIP archive
  with a SHA-256 checksum.

### Website update

The current information architecture, visual language, and responsive layout
remain unchanged. The update is deliberately incremental rather than a site
redesign.

- Update the header badge, hero download CTA, install CTA, metadata, and other
  visible current-version references to v0.4.0.
- Add a fourth `Display mode` / `显示模式` tab to the existing interactive
  product demo.
- The new demo panel shows a compact Side Panel / Floating Window selector and
  a visual floating-window preview that matches the extension UI.
- Explain that the floating window is global and unique, remembers its geometry,
  opens or focuses from the extension icon, and shares data with the Side Panel.
- Add v0.4.0 to the website release-history section while preserving v0.3.0 and
  earlier entries.
- Add or adjust FAQ copy so visitors understand that switching display modes
  requires one action and does not require opening another Fomo session.
- Point download links at the GitHub Release tag `v0.4.0` and its versioned ZIP
  asset.

## Changelog content

Move the current floating-window notes from `Unreleased` into a dated `0.4.0`
section. The release notes cover:

- the optional single global floating window;
- one-step switching between Side Panel and floating window;
- shared feed data and preferences across both surfaces;
- remembered floating-window size and position;
- automatic capture recovery and connection continuity during surface changes;
- stability work around atomic handoff, stale-window recovery, and isolated
  capture health checks.

The Chinese and English changelog sections remain equivalent in meaning.

## Files and components

- `package.json` and `pnpm-lock.yaml`: package version.
- `wxt.config.ts` or the existing manifest source: extension version if not
  inherited automatically.
- `CHANGELOG.md`: v0.4.0 release notes and reference link.
- `README.md`: current download/version references and feature summary.
- `website/index.html`: version labels, download URLs, display-mode demo, FAQ,
  and release-history content.
- `website/styles.css`: styles for the new demo panel using existing tokens and
  responsive conventions.
- `website/main.js`: tab behavior only if the existing generic tab controller
  does not already support the fourth panel.
- `website/homepage.test.mjs`: release links, version strings, demo semantics,
  and retained-history assertions.
- Release packaging output: v0.4.0 ZIP and checksum generated by the existing
  local packaging workflow.

## Interaction design

The new demo tab uses the same keyboard-accessible tab behavior as the current
Feed, Filters, and Settings tabs. Inside the panel, Side Panel is shown as the
default selected mode and Floating Window as the alternative. Selecting either
mode updates only the website demo; it does not attempt to control Chrome.

The floating preview remains compact and reuses the existing feed-card visual
language. Motion is limited to the current transition system and is disabled
under `prefers-reduced-motion`.

## Error and compatibility boundaries

- The website remains a static site with no new backend or analytics dependency.
- Existing download fallback behavior is preserved.
- No extension permissions are added for the release or website update.
- Chrome minimum-version claims must match the built manifest and README.
- Existing untracked design assets and user files are not modified or committed.

## Verification

Before integration:

1. Run TypeScript type checking.
2. Run the complete unit and integration test suite.
3. Run `website/homepage.test.mjs`.
4. Run Playwright end-to-end tests, including Side Panel to floating-window and
   floating-window to Side Panel switching.
5. Run the production Chrome Manifest V3 build.
6. Generate the v0.4.0 local package and verify its checksum and required files,
   including `floatpanel.html`.
7. Preview the website locally at desktop and mobile widths and verify all four
   demo tabs, download links, and release entries.
8. After merging into `main`, rerun the relevant verification from the merged
   tree before pushing and publishing the GitHub Release.

## Git and release flow

- Complete release changes on `test/sidepanel-new-page`.
- Preserve unrelated untracked files.
- Merge the branch into local `main` without rewriting history.
- Verify the merged result.
- Push `main` to `origin`.
- Create and push tag `v0.4.0`, then publish the GitHub Release with the ZIP and
  SHA-256 checksum assets.

## Acceptance criteria

- Chrome reports extension version 0.4.0 and the built package contains both
  Side Panel and floating-window entrypoints.
- The website visibly advertises v0.4.0 and downloads the v0.4.0 archive.
- The interactive product demo contains a working, accessible Display Mode tab.
- Website release history and `CHANGELOG.md` accurately describe v0.4.0.
- All automated checks pass before and after the merge to `main`.
- `origin/main` and the GitHub v0.4.0 Release contain the verified result.
