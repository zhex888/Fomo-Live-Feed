# Fomo Live Feed 原子界面切换设计

**日期：** 2026-09-06  
**状态：** 已确认  
**目标版本：** Chrome 141+

## 1. 目标

让侧边栏和悬浮窗成为同一套实时信息流的两种展示载体。用户只需执行一次切换操作，插件负责打开目标界面、同步完整状态并关闭原界面。切换不得中断 Fomo 实时采集，也不得要求用户刷新页面、重新打开标签页或配置额外选项。

任何时刻只保留一个 Fomo Live Feed 界面：侧边栏或悬浮窗。

## 2. 范围

本功能包括：

- 侧边栏与悬浮窗双向切换；
- 信息流、连接状态、筛选、设置、交易员备注和界面偏好的连续同步；
- 切换期间实时事件的无丢失、无重复衔接；
- 扩展更新或重新加载后的自动采集恢复；
- 目标界面失败时保留原界面的回退机制；
- 将最低支持版本从 Chrome 138 提升到 Chrome 141。

本功能不包括：

- 建立第二条 Fomo WebSocket；
- 让侧边栏和悬浮窗同时长期运行；
- 将数据同步到云端或其他浏览器；
- 绕过 Fomo 登录状态。

## 3. 已选方案

采用后台切换协调器。Service Worker 是连接与界面切换的协调中心，IndexedDB 和现有持久化设置是数据事实来源。侧边栏与悬浮窗只负责展示和发送用户操作，不持有必须传给另一界面的独占状态。

```text
Fomo page WebSocket
        |
        v
Background Service Worker
  - connection state
  - event ingestion and broadcast
  - persistent preferences
  - Surface Switch Coordinator
        |
        v
Side Panel <-------> Floating Window
```

不采用界面间直接复制状态，因为源界面关闭与消息传递之间存在竞态。不采用同时挂载两个界面，因为这与单界面要求冲突，并会产生重复查询和额外资源占用。

## 4. 状态所有权

### 4.1 后台与持久层

以下状态不属于任何具体界面：

- Fomo 标签页和 WebSocket 连接状态；
- 已接收事件及其稳定事件标识；
- 最新持久化事件游标；
- 活动筛选、链筛选和市值区间；
- 语言、声音、字体、颜色和显示模式设置；
- 交易员备注、标签、颜色、置顶和静音状态；
- 悬浮窗尺寸与位置。

实时事件继续先写入 IndexedDB，再广播给活动界面。界面关闭不会停止采集。

### 4.2 界面本地状态

只有短暂且无须跨界面延续的交互状态保留在组件内，例如按钮按压状态、当前 tooltip 和尚未提交的临时视觉反馈。打开的筛选或设置面板默认不跨界面恢复，避免切换后遮挡内容。

## 5. 切换协议

新增由后台拥有的 `SurfaceSwitchCoordinator`，并使用受校验的扩展消息：

- `surface.switch.request`：源界面请求切换目标模式；
- `surface.bootstrap`：目标界面请求当前快照和切换上下文；
- `surface.ready`：目标界面报告已加载快照并完成实时订阅；
- `surface.switch.result`：后台返回成功或封闭的失败原因。

每次切换生成唯一 `switchId`。后台只允许一个活动切换；相同请求幂等，过期响应不得关闭当前界面。

### 5.1 侧边栏切换到悬浮窗

1. 侧边栏发送切换请求，并将按钮置为忙碌状态。
2. 后台创建或聚焦唯一悬浮窗。
3. 悬浮窗从后台和持久层读取完整快照，记录快照事件游标，并注册实时消息监听。
4. 悬浮窗补齐快照之后到达的事件，然后发送 `surface.ready`。
5. 后台确认 `switchId` 和事件游标有效。
6. 后台通过 `chrome.sidePanel.close()` 关闭源侧边栏。
7. 后台持久化 `displayMode: "floating"` 并返回成功。

### 5.2 悬浮窗切换到侧边栏

1. 悬浮窗发送切换请求，并将按钮置为忙碌状态。
2. 后台基于原浏览器窗口调用 `chrome.sidePanel.open()`。
3. 侧边栏完成与悬浮窗相同的快照、订阅和补齐握手。
4. 后台确认目标已就绪后关闭悬浮窗。
5. 后台持久化 `displayMode: "sidepanel"` 并返回成功。

`displayMode` 只决定以后点击扩展图标时打开哪种界面，不决定实时连接是否存在。

## 6. 连接生命周期与自动恢复

正常界面切换不触碰 Fomo 页面、不重建内容脚本，也不重启 WebSocket。连接状态由 Fomo 内容脚本上报并由后台统一判断，两个界面读取相同结论。

后台把以下情况分开处理：

1. **正常切换：** 连接保持原样，目标界面直接继承连接快照。
2. **Service Worker 休眠：** 从 `chrome.storage.session` 恢复候选状态，并只信任仍然存在的 Fomo 标签页；随后等待内容脚本健康报告校准。
3. **扩展更新或手动重新加载：** 如果存在 Fomo 标签页，但没有当前版本的 observer 健康报告，后台只选择一个合适的已登录 Fomo 标签页自动刷新，使 `document_start` 内容脚本在 WebSocket 创建前注入。
4. **没有 Fomo 标签页：** 由明确的用户界面操作触发时，后台打开一个未激活的 Fomo 标签页用于恢复；不在后台无限创建标签页。
5. **未登录：** 检测到登录必要状态后停止自动刷新，向活动界面报告 `login-required`，等待用户完成登录。

自动恢复必须有单次飞行锁、冷却时间和每标签页尝试上限，防止刷新循环。恢复动作不得同时刷新多个 Fomo 标签页。

## 7. Chrome 版本要求

清单中的最低 Chrome 版本提升到 141。原因是 `chrome.sidePanel.close()` 从 Chrome 141 开始提供，而完整的“目标就绪后自动关闭源侧边栏”依赖该 API。

不为 Chrome 138–140 提供只能打开但不能可靠关闭源界面的降级行为，以免产生两个同时运行的界面。

## 8. 错误处理

- 目标界面创建、打开、初始化或追平超时：取消切换，保留源界面和原显示模式。
- 连续点击：后续相同目标请求复用当前 Promise；相反目标请求在当前切换结束后重新评估。
- 悬浮窗被用户手动关闭：清理 session window id，不影响采集与历史。
- Service Worker 在切换中重启：从 session 中的切换记录恢复；无法证明目标已就绪时保留可见源界面，不盲目关闭。
- 关闭源界面失败：目标界面保留，显示一次非阻塞提示，并允许重试关闭；后台不得反复自动创建目标界面。
- 数据库查询失败：目标界面不得报告 ready，原界面继续存在。
- 自动连接恢复失败：保留历史只读能力，并展示准确的离线或登录提示。

失败原因使用封闭枚举，不跨边界传递原始异常、页面内容、身份凭据或 WebSocket 数据。

## 9. 用户界面

- 设置中继续保留默认显示模式选择。
- 侧边栏和悬浮窗都提供明确的“切换到悬浮窗”或“切换到侧边栏”操作。
- 切换期间显示简短的“正在切换…”反馈并禁用重复点击。
- 成功切换不显示多余通知；目标界面直接呈现已有信息流。
- 失败时原界面保持可用，并显示可重试的非阻塞错误。

## 10. 测试与验收

### 10.1 单元测试

- 协调器的成功、超时、幂等、并发和过期 `switchId` 行为；
- 目标未 ready 时绝不关闭源界面；
- 正确调用 `sidePanel.open()`、`sidePanel.close()` 和 `windows.remove()`；
- 快照游标与切换期间事件补齐；
- Service Worker 重启后的 session 恢复；
- observer 缺失、自动刷新冷却、尝试上限和登录停止条件；
- 设置持久化失败时不产生错误的默认模式。

### 10.2 浏览器集成测试

- 侧边栏切到悬浮窗后只剩悬浮窗，已有事件、筛选和设置一致；
- 悬浮窗切回侧边栏后只剩侧边栏；
- 切换期间注入新事件，目标界面无丢失、无重复；
- 快速重复切换始终只有一个界面；
- 目标创建失败时原界面保留；
- Fomo WebSocket 在正常切换中不重建；
- 扩展重新加载后 observer 缺失时自动恢复；
- 未登录时停止刷新并显示登录提示；
- manifest 声明 Chrome 141+。

### 10.3 完成标准

用户在任一界面执行一次切换后，无需刷新、重新打开或额外设置即可在目标界面继续查看同一信息流。目标界面确认就绪后源界面自动关闭；切换期间产生的事件全部且只展示一次；正常切换不改变 Fomo 连接。

## 11. 安全与隐私

本功能不新增外部服务、账号、鉴权缓存或云同步。自动恢复仅对清单中允许的 `https://fomo.family/*` 和 `https://www.fomo.family/*` 标签页生效。现有消息发送者校验、URL 白名单和数据最小化约束继续适用。
